# アーキテクチャ決定記録

アーキテクチャ決定記録（ADR）は、長く効く決定について、採用理由、検討した
選択肢、受け入れる影響を残すための文書。

## 配置場所

- `docs/adr/` には、リポジトリ全体に適用する決定を置く。
- `products/<category>/<product>/docs/adr/` には、そのプロダクトだけに適用する
  決定を置く。

## ADR を作るとき

長期的な影響があり、意味のある選択肢やトレードオフを伴う決定をする前、または
同時に ADR を作る。対象は、リポジトリ構成、CAD ツール、製法、材料方針、配列、
マウント方式、PCB アーキテクチャ、ファームウェア基盤など。

日常的な寸法調整、試作結果、見積もり、作業ログには ADR を使わない。対象の CAD、
製造、またはプロダクト文書に記録する。

## ファイル名と状態

ADR ディレクトリごとに独立して連番を振る。ファイル名は4桁の連番と kebab-case の
スラッグを使う。例: `0001-cad-source-and-exports.md`。

状態は次のいずれかを使う。

- `提案`: 検討中で、まだ採用していない
- `承認`: 採用済みで、現在有効
- `廃止`: 後継なしで適用を終えた
- `置換`: 新しい ADR に置き換えた。置換先へリンクする

承認済み ADR の判断内容は書き換えない。判断を変えるときは新しい ADR を作り、旧
ADR を `置換` にして新旧の ADR から相互にリンクする。判断を変えない編集上の修正は
許容する。

## テンプレート

[template.md](template.md) を対象の ADR ディレクトリへ複製して、全ての節を埋める。
決定が影響する場合は、同じ変更で関連する `AGENTS.md`、README、製造文書も更新する。
