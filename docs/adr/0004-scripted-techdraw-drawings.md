# ADR-0004: TechDraw の図面をスクリプトで生成する

- 状態: 承認
- 日付: 2026-10-12

## 背景

[ADR-0003](0003-code-cad-source-of-truth.md) では、FreeCAD の図面の元データ
（`.FCStd`）を `drawings/` に置き、発注や図面確認の節目で更新するとした。

一方で、取り込んだ STEP はパラメトリックではない。GUI で付けた TechDraw の寸法は
頂点名や稜線名を参照するため、形状が変わると参照が外れる。試作の初期は、ドナー部品の
実測などで形状が大きく変わることが分かっている。そのたびに寸法を手で付け直すと、
図面の更新が節目でも負担になり、図面と形状が食い違ったまま残るおそれがある。

## 決定

TechDraw の図面は FreeCAD のスクリプトで生成し、`.FCStd` は生成物として扱う。

- どの寸法を、どの頂点の間に、どの値で入れるかは、コード CAD 側で図面仕様として
  定義する。図面仕様はビルドで `cad/export/` に JSON として出力し、テストで検証する。
- FreeCAD 側のスクリプトは `drawings/` に置く。STEP と図面仕様を読み、投影図と寸法を
  作る。寸法の測定値が図面仕様の期待値と合わなければ、エラーにして保存しない。
- 生成した `.FCStd` は `cad/export/` に出力し、コミットしない。
- 寸法入り図面として残すのは、レビューや発注の節目で書き出した PDF だけとする。
  PDF は `drawings/` にコミットする。発注に使った PDF は、ほかの生成物と同じく
  `manufacturing/<service>/<rev>/` にもコピーする。
- FreeCAD は CI で動かさない。図面仕様の生成と検証は CI のテストに含める。

## 検討した選択肢

- GUI で作った `.FCStd` をコミットする（ADR-0003 の当初案）: 図面を自由に描ける。
  ただし、形状を変えるたびに寸法の参照を手で直す必要があり、差分レビューもできない。
- スクリプトで生成し、`.FCStd` もコミットする: GUI で手を入れた結果を残せる。
  ただし、再生成すると手で直した部分が上書きされ、どちらが正本か曖昧になる。
- スクリプトで生成し、節目の PDF だけをコミットする: 形状を変えたら再実行するだけで
  寸法が付き直り、寸法の値も自動で検証できる。図面の体裁を GUI で細かく直す運用は
  できない。

## 影響

- 形状を変えたら `tsugu65-build` と図面生成を再実行するだけで、図面が追従する。
  寸法の参照が外れる問題は起きない。
- 新しい寸法を図面に入れるときは、コード CAD 側の図面仕様とそのテストを変更する。
- 図面生成にはローカルの FreeCAD（1.1 以上）が必要。FreeCAD 同梱の Python は 3.11
  なので、`drawings/` のスクリプトは 3.11 で動く構文と標準ライブラリだけで書く。
- PDF の書き出しは今のところ GUI で行う。
- ADR-0003 のうち、図面の元データと更新方法の扱いをこの ADR で置き換える。コード CAD
  を正本とする決定はそのまま有効。
